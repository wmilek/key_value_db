# Observations for `l0_timing.py derive` — nRF5340-DK, MX25R6435F, flash_area
#
# NOT a benchmark output. These are the three raw UART captures from
# app_perf/RESULTS.md that were taken on the flash_area backend, copied here
# verbatim so a derived model has a checked-in, quotable input. Provenance and
# board details are in that file; the setup is
#
#   nRF5340-DK (PCA10095) cpuapp, storage_partition on the on-board
#   MX25R6435F QSPI NOR: 8 MB, 64 KB erase blocks, 8 MHz Quad-SPI,
#   flash_area_align() = 4. Zephyr build 4a405846193f.
#
# The UBI capture in RESULTS.md is deliberately NOT here: UBI issues flash
# operations of its own beneath the seam where CONFIG_BLOB_DB_IOSTATS counts,
# so its wall-clock includes traffic its counters do not report, and every
# such observation would push the fitted per-operation costs upward.
#
# The `255ce7a` capture is not here either: that commit predates the I/O
# counters, so its phases have wall-clock and nothing to attribute it to.
#
# Regenerate this file if RESULTS.md gains a new flash_area capture:
#   sed -n '473,600p' app_perf/RESULTS.md >> this file
