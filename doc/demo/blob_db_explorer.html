blob_db Bucket-Log Explorer

A step-by-step simulator of the v1 allocator in lib/blob_db. Each bar is one erase sector, drawn to scale in bytes. Run an operation and watch the flash reads, writes and erases it costs, in the same order the C code issues them. Models the raw flash_area backend.

      Model. These follow the C code: scan_bucket_for reads 12 B (slot header + id) per slot plus one probe of the erased tail. slot_verify reads the payload and the 2 B CRC. Compaction reads the whole sector, then does master → scratch → bucket → scratch → master, which is five erases on raw NOR (write_master erases before writing). Ids map to id % buckets; sectors 0–2 are master A, master B and scratch.

      Known issue in the current code. build_compacted_image() walks slots with slot_view_at(), which returns false on a CRC mismatch, and it treats that as end-of-log. Lookups instead step over a CRC-bad slot. So if a torn or rotten slot has valid slots after it, the next compaction of that bucket drops them. The last scenario reproduces this.

      Simplified. UBI, timing, crashes inside compaction, bit rot and the batch API are not modelled. Bucket counts are kept small so the bars stay readable. A real 8 MB partition has 2045 (4 KB) or 125 (64 KB) buckets.
